# 方法学备忘录

本项目执行过程中实际遇到的坑与解决方案。部分是通用经验，
部分是 GHSR1a / GPCR 特有的。按工作阶段组织。

## 一、环境配置

### 1.1 Anaconda 服务条款拦截（conda ≥ 25.x）

**现象**：`CondaToSNonInteractiveError`，建环境时直接失败。

**原因**：新版 conda 会 fallback 到 Anaconda 商业频道并要求接受服务条款。
机构用户（高校）接受条款存在合规灰度。

**正确解法是绕开，不是接受**（两个字段都要改，只改 `channels` 不够）：

```bash
conda config --remove channels defaults
conda config --add channels conda-forge
conda config --remove-key default_channels
conda config --add default_channels https://conda.anaconda.org/conda-forge
conda config --set channel_priority strict
```

`default_channels` 是最容易漏的一个——漏了的话，`channels` 虽然干净，
但建环境时仍会 fallback 到商业频道。

### 1.2 装包前必须 dry-run（本项目靠这条拦下一次事故）

**教训**：一次性装 8 个包触发依赖冲突，而 conda 的 libmamba solver
在生成冲突解释时自己崩溃（`RuntimeError: bad_variant_access`，已知 bug），
把真实原因完全掩盖，屏幕上只剩一堆无意义 traceback。

**排查方法**——逐个包 dry-run：

```bash
for p in gemmi openbabel mdtraj boost-cpp swig; do
  out=$(conda install -n aidd --dry-run -y -c conda-forge $p 2>&1)
  echo "$out" | grep -q "DOWNGRADED" && echo "$p 会降级" || echo "$p 安全"
done
```

**本环境实测的危险品清单**：

| 包 | 后果 |
|---|---|
| `boost-cpp` / `swig` | RDKit 2026.03.5 → 2024.03.6，libboost 1.90 → 1.84 |
| `mdtraj` | numpy 2.2.6 → 1.26.4，pandas 2.3.3 → 2.2.2 |
| pymol-open-source / pdbfixer / openbabel / gemmi | 安全 |

**原则**：
1. 不要一次装一堆包
2. 编译型依赖（boost、swig、cuda）一律放独立环境，失败也伤不到主环境
3. strict 优先级会让冲突更早暴露，这是好事，别放宽它
4. 装包前记下关键版本号，装完核对

### 1.3 AutoDock Vina 在 Apple Silicon 上装不了

穷尽尝试后的结论，**不必再试**：

| 尝试 | 结果 |
|---|---|
| conda-forge `osx-arm64` | 无构建 |
| `pip install vina` | 找不到 Boost |
| 独立环境 + boost-cpp + swig | 失败 |
| `--no-build-isolation` | 失败 |
| 设 `CONDA_PREFIX` + `BOOST_ROOT` | 失败（boost 头文件确认存在，但 vina 的 setup.py 不认） |

**替代方案**：CB-Dock2（https://cadd.labshare.cn/cb-dock2/php/index.php），
中科院团队开发，后端即 AutoDock Vina，国内可直接访问。
本机负责结构准备与结果分析，对接交给在线服务器——这种分工在工业界很常见。

## 二、数据获取与清洗

### 2.1 ChEMBL 物种过滤

人源 GHSR1a 是 `CHEMBL4616`。不要混入 `CHEMBL3278`（大鼠）/ `CHEMBL3428`（小鼠），
跨物种活性不可合并。

### 2.2 RCSB API 字段名（差点导致误判）

查询配体时，早期代码用了 `nonpolymer_entity_ids`，返回空，
一度以为 anamorelin 未被建模。正确字段是 **`non_polymer_entity_ids`**。
一个下划线的差别，差点让整个结构方案作废。

### 2.3 9UY3 没有传统 PDB 格式

RCSB 下载 `.pdb` 返回 404——结构过大超出 PDB 格式限制，只有 mmCIF。
这是现代 Cryo-EM 结构（尤其 GPCR-G 蛋白复合物）的常态。

本项目写了纯标准库 mmCIF 解析器处理（`scripts/structure/prepare_9UY3.py`），
不依赖任何第三方包。

### 2.4 实体标注残基数 ≠ 实际坐标残基数

9UY3 链 R 的 entity 标注是 676 残基，**实际坐标只有 283 个（37–334）**。
断点在 241|257，是 ICL3 柔性区未建模。
好消息是无 BRIL 融合标签坐标，不需要切融合蛋白。

**务必以坐标文件为准，不要信 entity 标注。**

## 三、结构处理

### 3.1 PDBFixer API 变化（版本 ≥ 1.9）

`findMissingAtoms()` 必须**显式调用**，旧版在 `addMissingAtoms()` 内部自动调用。
漏掉会报 `AttributeError: 'PDBFixer' object has no attribute 'missingAtoms'`。

正确顺序：

```
findMissingResidues → findNonstandardResidues → replaceNonstandardResidues
→ removeHeterogens → findMissingAtoms → addMissingAtoms → addMissingHydrogens
```

### 3.2 质子化状态：GHSR1a 的硬约束

E124³·³³ 与 R283⁶·⁵⁵ 之间的盐桥把配体口袋劈成两个腔，这是 GHSR1a 在已解析
GPCR 中**独有**的结构特征。因此：

- **E124 必须去质子化**（Glu⁻）
- **R283 必须质子化**（Arg⁺）

设反了盐桥不成立，口袋几何塌掉，之后所有对接结果作废。

### 3.3 盐桥距离作为基准值

```
E124 OE2 — R283 NH2 = 2.56 Å（真正的盐桥）
OE1—NH1 3.37 / OE1—NH2 3.62 / OE2—NH1 3.67 Å
```

**每做一步结构处理（加氢、能量最小化、MD）都应回来复测。**
偏离 > 0.3 Å 说明质子化或构象出问题，该结构不可用于对接。

本项目实测：加氢后仍为 2.56 Å，口袋几何未受影响。

### 3.4 PyMOL 对象名

用 `pymol 9UY3.cif` 打开时，对象被自动命名为 `9UY3`（文件名），
不是脚本里 `load ..., ghsr` 自定义的 `ghsr`。名字对不上时所有选择语句都会报
`Invalid selection name`。

修复：`set_name 9UY3, ghsr`

量距离用 `distance 名, 选择1, 选择2`，**要指定到具体原子**
（`name OE2`、`name NH2`），否则 PyMOL 取几何中心，读到的不是盐桥长度。

### 3.5 组氨酸质子化

结构中有 3 个 HIS：HIS186、HIS258、**HIS280**。
HIS280 = H280⁶·⁵²，属于激活机制核心芳香簇（F279⁶·⁵¹ / H280⁶·⁵² / F312⁷·⁴²）。
PDBFixer 不细分 HID/HIE/HIP，若要精确建模激活机制需用 PROPKA 或 H++ 单独判断。

## 四、对接与 RMSD

### 4.1 RMSD 的概念陷阱（最重要）

`rdMolAlign.GetBestRMS` **会先做最优叠合**（旋转 + 平移对齐）。

实测：配体整体平移 (1, 1, 1) Å 后

| 算法 | 结果 | 含义 |
|---|---|---|
| 不叠合的逐点比较 | **1.73 Å** | ✓ 真实位置偏差 |
| GetBestRMS（叠合后） | **0.00 Å** | ✗ 位移被消掉 |

**Redocking 判定必须用不叠合的逐点比较**，因为要回答的是
"有没有放回原位"，而非"构象长得像不像"。

若对接输出与晶体不在同一坐标系，正确做法是**先叠合受体**、
再算配体 RMSD——不要把配体对配体直接叠合。

### 4.2 CONECT 记录不保存键级

CB-Dock2 输出经 OpenBabel 转 PDB 后，**CONECT 只记录连接关系不记录键级**，
导致 RDKit 读出的结构里：羰基 C=O → C-O，苯环 → 环己烷，吲哚 → 饱和杂环。

**坐标是对的，只是键标注错了。** 这会让 `GetBestRMS` 因键序不同报
"No sub-structure match"，也会让 `Chem.RemoveHs` 失效。

绕法：手动按原子序数过滤氢，而不是依赖 RDKit 的 `removeHs=True`。

### 4.3 原子顺序自检

逐点比较的前提是原子顺序一致。用内部距离矩阵相关性自检：

```python
corr = np.corrcoef(D_ref[np.triu_indices(n,1)], D_dock[np.triu_indices(n,1)])[0,1]
```

- `r > 0.95`：顺序一致，可直接逐点比较
- `r < 0.5`：顺序错乱，逐点比较无效

本项目实测 r = 0.896，3.30 Å 是真实偏差而非脚本 bug。

### 4.4 CB-Dock2 的输出文件格式

- `fitdock_em_N.<score>.pdb` —— 纯配体，与输入同坐标系 ← **用这个**
- `out_N.<score>.pdb` —— 口袋残基 + 配体混合，坐标系已变，残基名全是 `UNL` ← 不能用

另外 CB-Dock2 的 "Top 5" 通常是 **5 个不同口袋**（它主打盲对接），
不是同一口袋的 5 个构象。所以 Best-of-5 对它意义有限。

### 4.5 本项目的 redocking 结果

Top-1 RMSD = **3.30 Å**（未达标，阈值 2.0 Å）。

诊断：质心距离仅 0.78 Å → **口袋找对了**；
逐原子位移中位数 1.28 Å、最大 7.74 Å →
吲哚环与苄基苯环锚定准确（0.35–0.60 Å），
哌啶环与二甲基氨基甲酰基的柔性尾巴转错方向（4.7–7.7 Å）。

anamorelin 约 10 个可旋转键，是典型的可旋转键采样问题。
CB-Dock2 不提供 exhaustiveness 调节，属工具固有限制。

**可用边界**：打分可用于排序；具体结合模式不可全信。

## 五、建模与评估

### 5.1 Scaffold Split 的严厉程度取决于数据结构

反直觉的实测结果：随机切分 → Scaffold split，MAE 从 0.617 → 0.615，几乎没动。

**原因**：本数据集骨架高度碎片化（889 个小分子 / 385 种骨架，2.3 化合物/骨架）。
同骨架分子本就稀少，随机切分时也很难同时落进训练/测试集，
所以 scaffold split 要惩罚的"抄袭"本来就不易发生。

**结论**：骨架越集中（每骨架几十上百个分子），随机切分水分越大；
越碎片化两者越接近。但**事先不知道会是哪种情况，所以必须做**。

### 5.2 失效临界点：0.6

测试分子与训练集的最大 Tanimoto 相似度低于 0.6 时，模型退化成昂贵的平均值猜测器。

| 相似度 | MAE |
|---|---|
| 0.00–0.50 | 1.036 |
| 0.50–0.60 | 0.881 |
| **0.60–0.70** | **0.693** |
| 0.70–0.85 | 0.661 |
| 0.85–1.00 | 0.644 |

最终模型上再次验证：域内 R² = 0.444，域外 **R² = −0.655**。
**域外 R² 为负意味着不如直接猜平均值——不只是不准，是有害。**

两组独立数据（1780 个测试分子的分层诊断、最终模型的 178 个测试分子）
指向同一门槛，互相印证。

这个临界点**换更强的模型也改不了**，它是数据的性质，不是模型的问题。

### 5.3 ExtraTrees 在稀疏二值指纹上崩了

同样用 Morgan 指纹：RandomForest 0.401，ExtraTrees **0.061**。

原因：ExtraTrees 在每个分裂点随机选阈值，而 Morgan 指纹是 2048 维稀疏
二值向量（绝大多数位置为 0），随机阈值在这种特征上几乎提不出信息。

**模型没有万能的，得看特征的脾气来选。**

### 5.4 XGBoost / LightGBM 未能超越基线，但结论要看指标

| 指标 | XGBoost vs GradientBoosting |
|---|---|
| R² | 胜 2/5，差值 −0.005（std 0.034）→ **纯噪声** |
| MAE | 胜 **5/5**，差值 −0.018 → **稳定真实改善** |

MAE 对异常值鲁棒，R² 含平方项对大误差敏感。XGBoost 的正则化让它在多数
样本上更准（MAE 好），但对极端活性值预测偏保守（R² 受损）。

**药物发现中 MAE 更重要**——关心的是典型分子的误差，而非拟合极端值。

XGBoost 在此无优势的三个原因：样本量小（711 训练样本）、
特征高度稀疏、数据本身噪声大（ChEMBL 多实验室汇总）。

**结论：换模型这条路已到头。想再提升要靠数据和特征，不是算法。**

### 5.5 先量化数据质量再建模

- **SAR 强度**（骨架内 pAffinity 加权 std / 全局 std）= **0.687**
  → 骨架解释掉约 31% 的活性变异，构效关系真实存在。
  若该值接近 1.0，说明骨架不携带信息，任何模型都只是在拟合噪声。
- **活性悬崖比例** = **8.8%**（Tanimoto > 0.55 的相似对中，活性差 > 100 倍的占比）
  → <10% 干净，10–20% 可接受，>20% 需排查 assay 来源。

### 5.6 交叉验证关键结论

- 口袋残基：自写脚本算出 27 个，PyMOL 独立验证同为 27 个
- 失效临界点 0.6：分层诊断与最终模型实测共同印证
- logP 重要性（排列重要性排第二）与结构发现（Cavity II 是疏水腔）互相印证

**两条独立路径指向同一结论时，结论的可信度显著提升。**

## 六、通用工作方式

### 6.1 先验证可行性，再投入

GHSR 在心脏 bulk 转录组中几乎测不到（FPKM 0.001，0/16 检出），
而管家基因是它的 20 万倍。5 分钟的数据检查排除了一个不可行方向，
并把它转化成了更好的问题（GHSR 是否在特定细胞亚群表达？）。

**用最小代价证伪，比在错误方向上耗几周更有价值。**

### 6.2 负面结果也是产出

Redocking 未达标、XGBoost 未超越基线，均完整记录并给出诊断。
界定"什么情况下不能用"比报一个漂亮分数更有价值——
这也是本项目在方法学上最值得称道的部分。

### 6.3 一个夸张但站不住脚的结论，不如一组平淡但可靠的数据

初版用 Butina cutoff=0.65 跑出 R² ≈ 0（比猜平均值还差），
但那只聚出 34 个簇、最大簇 285 个分子，测试集与训练集相似度被压到 0.25——
那已不是"新骨架"而是"完全不同的化学类型"，真实场景不会出现。
改成扫描四档 cutoff 做成连续光谱后，结论才站得住。
